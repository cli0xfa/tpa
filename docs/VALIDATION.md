# 本机验证记录

日期：2026-10-15（Asia/Shanghai）。

## 环境

- Windows 11 专业工作站版 Insider Preview，10.0.29683。
- AMD Ryzen 5 5600G，6 核 / 12 线程。
- Rust 1.95.0，FFmpeg / ffprobe 7.1。
- WASAPI 默认设备，48 kHz、双声道、浮点采样。
- Windows ConPTY，160×51 终端、160×45 字符画面，半块真彩色。

## 已完成

- 格式检查、Clippy 零警告、Rust 全目标测试。
- 14 个单元测试、8 个常规媒体集成测试通过；真实音频设备测试额外显式运行并通过，共 23 个测试。
- 同步闪光/提示音，以及音轨延迟 250 ms、视频轨延后起播、非零容器起点和跳转后的共同时间轴验证通过。
- MP4、MKV、WebM、变帧率、旋转、非方形像素、极短片段、未知时长裸 H.264、损坏文件、特殊字符路径和满队列退出验证通过。
- Windows ConPTY 黑盒检查：声音、暂停、模式切换、跳转、缩小自动暂停、恢复播放、保留手动暂停和正常退出通过；160×45 半块真彩色正常负载下实测约 29.8–30.1 FPS。
- 显式真彩色在 `NO_COLOR=1` 环境下仍生效；测试捕获了实际 RGB ANSI 控制序列。
- Rust 1.88 Windows GNU 全目标编译检查通过。
- macOS ARM64 条件代码交叉编译检查通过；这不等同于 macOS 链接、实际播放或声音验收。
- Windows x64 MSVC 发布程序静态链接 C 运行时；导入表只包含 Windows 系统库。

## 持续播放

完整检查执行 1800.007 秒，正常退出（退出码 0），无音频报错。

| 指标 | 实测 |
|---|---:|
| 渲染新视频帧 | 52,317 |
| 全程平均帧率（包含重播与编译压力） | 29.06 FPS |
| 调度丢帧 | 1,293 |
| 平均字符渲染耗时 | 0.579 ms |
| 最大字符渲染耗时（包含调度延迟） | 68.349 ms |
| 最大帧与播放时钟间隔（包含编译压力） | 197.333 ms |
| 播放器私有内存（正常播放采样） | 5.00–5.36 MiB |
| 最后一次采样的播放器私有内存 | 5.31 MiB |

内存按分钟采样，共 30 次；重播时短暂释放解码器，最低采样为 3.64 MiB。没有出现随帧数增长的内存堆积。原始日志与 CSV 保存在本地 `target/verification/soak-final.log` 和 `target/verification/memory-final.csv`（构建产物，不提交到 Git）。

正常负载的同步与真实设备测试满足 100 ms 目标；并行编译压力下的最大间隔超过 100 ms，因此不承诺高负载下始终保持该上限。首次约 22 分钟的中断检查没有计入这次完整 30 分钟结果。

检查使用 `verify_playback`、160×45 TestBackend、60 秒 MPEG-4/AAC 测试片段反复重播和真实音频设备，记录播放器及 FFmpeg 子进程私有内存。TestBackend 不包含终端输出；真实终端刷新率由上述 ConPTY 检查单独记录。检查期间还进行过并行编译，因此压力时的丢帧不能当作空闲负载下的刷新率。
