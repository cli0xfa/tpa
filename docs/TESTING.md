# 桌面验收与性能记录

## 自动检查

运行 README 中的格式、Clippy、全目标测试与真实设备测试。媒体集成测试中的闪光/提示音比较的是解码后的共同时间轴；设备测试进一步检查暂停、跳转和音频时钟驱动的视频时间误差。

## 真实终端验收

在 Windows Terminal、macOS 终端、Linux 终端各执行一次。记录操作系统、终端版本、字体、CPU、视频编码及尺寸、颜色模式、窗口大小和实际刷新率。

1. `tpa doctor`，确认 FFmpeg、ffprobe 和音频设备。
2. `tpa browse <目录>`：上下选择、进入目录、返回上级、输入筛选、打开中文及空格路径。
3. 使用含人声的视频检查可理解的彩色画面与声音。依次切换半块、盲文、ASCII，确认不重置进度。
4. 暂停 5 秒再继续，快速连续前后跳转，调整音量并切换静音，确认声音和画面没有旧数据串入。
5. 调整窗口大小，切换控制栏；缩小至 40×12 以下确认自动暂停，恢复后继续；手动暂停状态不能被窗口恢复取消。
6. 打开帮助、返回浏览器、取消正在进行的探测；播放结束后检查保留最后一帧和 Enter 重播。
7. 用同步闪光/提示音视频检查可感知的同步误差，目标 ≤100 ms。设备缓冲、终端阻塞和调度负载可能影响结果，异常时记录环境。
8. q、Ctrl+C 和外部可捕获终止信号分别退出，确认光标、终端输入及原屏幕恢复，没有本次播放遗留的 FFmpeg 进程。
9. 移除默认音频设备或用 `--no-audio`，确认能继续无声播放；损坏文件和不存在的路径应显示可读错误。

## 性能与持续播放

Windows Terminal 性能基线使用 160×51 窗口（视频区 160×45），半块真彩色，60 FPS；高分辨率压力档使用 240×73（视频区 240×67），30 FPS。运行 `tpa play <视频> --fps 60 --quality fixed` 和 `tpa play <视频> --fps 30 --quality fixed`，分别观察界面显示的刷新率、字符渲染耗时、终端写入耗时、调度延迟、取帧耗时和丢帧数，并用 `tools/measure_memory.ps1` 采集播放器及 FFmpeg 内存。另用默认 `--quality auto` 验证负载持续过高时画面和帧率会逐级自适应，负载恢复后画质逐级恢复。

CI 的 ConPTY 作业覆盖 60 FPS 参数以及 160×51 与 240×73 窗口缩放，验证控制、尺寸重建和退出行为；它不代表 Windows Terminal 的实际渲染性能。人工验收记录 Windows Terminal 版本、字体、CPU、视频编码/尺寸、色彩模式和实测数据。目标是在 Ryzen 5 5600G 参考机上，160×45 字符画面接近 60 FPS，240×67 字符画面接近 30 FPS。

运行 `verify_playback` 1800 秒，在每分钟记录中确认没有错误、持续缓冲或不断增加的内存占用。Windows 内存采样脚本输出 CSV。排除首次加载及缓存预热后，比较播放器私有内存的范围与趋势，并单独观察 FFmpeg 子进程。长时间检查输出的 FPS 是已显示新视频帧数/总时间，包含重播开销；TestBackend 不包含真实终端输出时间。

## 当前环境的边界

此仓库在 Windows 桌面实现。CI 配置可以在推送到 GitHub 后自动执行跨平台检查；未运行的 macOS/Linux 桌面验收不能标记为通过。具体本次实测结果记录在 `docs/VALIDATION.md`。

Windows ConPTY 黑盒检查同时覆盖真实程序的彩色输出、按键、跳转、自动暂停、缩放恢复、保留手动暂停和正常退出，CI 的 Windows 作业会运行无声版本。它验证伪终端协议与程序行为；字体外观和主观可辨认程度仍需要实际终端中检查。
